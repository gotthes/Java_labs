# Задание 1. Классы

## Задача 2
### Текст задачи
Человек. Создайте сущность Человек, которая описывается: Имя: строка; Рост: целое число. Может возвращать текстовое представление вида «Name, рост: height», где Name и height — переменная с именем и ростом. Необходимо создать и вывести на экран людей: Клеопатра (152), Пушкин (167), Владимир (189).

### Алгоритм решения
Создан класс `Human` с двумя приватными полями `name` и `height`. Единственный конструктор принимает оба значения и сохраняет их через `this.name = name` и `this.height = height`. Метод `toString()` переопределён (`@Override`) и возвращает строку нужного формата простой конкатенацией `name + ", рост: " + height`. В `main` создаются три объекта `Human` с разными значениями и печатаются через `System.out.println`, который сам вызывает `toString()`.

## Задача 3
### Текст задачи
Имена. Создайте сущность Имя, которая описывается тремя параметрами: Фамилия, Личное имя, Отчество. Имя может быть приведено к строковому виду, включающему традиционное представление всех трёх параметров: Фамилия Имя Отчество. Необходимо предусмотреть возможность того, что какой-либо из параметров может быть не задан, и в этом случае он не учитывается при приведении к текстовому виду. Создать имена: Клеопатра; Пушкин Александр Сергеевич; Маяковский Владимир.

### Алгоритм решения
Создан класс `Name` с тремя полями: `lastName`, `firstName`, `patronymic`. Конструктор принимает все три параметра в этом порядке, не заданная часть передаётся как `null`. В `toString()` строка собирается через `StringBuilder` и приватный статический метод `append(sb, part)`: если переданная часть `null` или пустая (после `trim()`), она пропускается; если в `sb` уже что-то накоплено, перед следующей частью добавляется пробел-разделитель. Так лишние пробелы вокруг незаданных частей не возникают. Созданы три объекта: `new Name(null, "Клеопатра", null)`, `new Name("Пушкин", "Александр", "Сергеевич")`, `new Name("Маяковский", "Владимир", null)`.

Человек с именем. Объедините сущности Человек из задачи 1.2 и Имя из задачи 1.3 таким образом, чтобы имя человека задавалось с использованием сущности 1.3, а не строки. # Задание 3. Ссылки между объектами

## Задача 3
### Текст задачи
Города. Создайте сущность Город, которая будет представлять собой точку на карте со следующими характеристиками: Название города; Набор путей к следующим городам, где путь представляет собой сочетание Города и стоимости поездки в него. Кроме того, Город может возвращать текстовое представление в виде названия города и списка связанных с ним городов (в виде пары «название:стоимость»). Используя разработанную сущность, реализовать схему с рисунка 2 (города A, B, C, D, E, F и пути между ними).

### Алгоритм решения
Созданы два класса. `Route` хранит путь: поле `destination` типа `City` и поле `cost`; `toString()` возвращает `destination.getName() + ":" + cost` — берётся только имя города назначения, а не его полный `toString()`, иначе при взаимных путях получилась бы бесконечная рекурсия (A печатает путь в B → B печатает путь обратно в A → ...). `City` хранит `name` и `List<Route> routes`. Сначала все шесть городов создаются пустыми конструктором `City(String name)`, который инициализирует `routes` пустым `ArrayList`. Затем методом `addRoute(City destination, int cost)` пути добавляются в список — он создаёт `new Route(destination, cost)` и кладёт его в `routes`. Так можно связать города, даже если в момент создания одного из них другой ещё не существовал. Двусторонние пути (одинаковая стоимость в обе стороны) добавляются вспомогательным методом `twoWay`, вызывающим `addRoute` у обоих городов сразу. `toString()` города собирает строку вида `"A -> [F:1, B:5, D:6]"` через `StringBuilder`, проходя по списку `routes` в цикле и вставляя запятую перед каждым элементом, кроме первого.

# Задание 4. Конструкторы по альтернативным наборам параметров

## Задача 8
### Текст задачи
Создаём Города. Измените сущность Город из задачи 3.3. Новые требования включают: Город можно создать, указав только название; Город можно создать, указав название и набор связанных с ним городов и стоимостей путей к ним.

### Алгоритм решения
У класса `City` появился второй конструктор — `City(String name, Route... routes)`, использующий переменное число аргументов (varargs). Первой строкой он вызывает `this(name)`, то есть первый конструктор, который записывает имя и создаёт пустой список — так инициализация не дублируется. Затем циклом `for (Route route : routes)` каждый переданный путь добавляется в `this.routes`. Это позволяет либо создать город пустым (`new City("D")`), либо сразу с готовыми путями (`new City("E", new Route(d, 2))`, `new City("F", new Route(b, 1), new Route(e, 2))`). Пути, которые нельзя было указать при создании города (потому что город назначения ещё не существовал), дописываются позже через `addRoute`, как и в задаче 3.3.

# Задание 5. Неизменяемые объекты и перегрузка методов

## Задача 5
### Текст задачи
Дроби. Создайте сущность Дробь со следующими особенностями: имеет числитель и знаменатель (целые числа); может быть создана с указанием числителя и знаменателя; может вернуть строковое представление вида «числитель/знаменатель»; может выполнять операции сложения, вычитания, умножения и деления с другой Дробью или целым числом, при этом результатом операции должна быть новая Дробь, а исходные дроби не изменяются. Создать несколько дробей, продемонстрировать каждую операцию, и посчитать `f1.sum(f2).div(f3).minus(5)`.

### Алгоритм решения
Создан класс `Fraction` с полями `final int numerator` и `final int denominator` — модификатор `final` гарантирует, что после создания объект больше нельзя изменить. Конструктор проверяет знаменатель на ноль (бросает `IllegalArgumentException`), а также сразу сокращает дробь через наибольший общий делитель, который считается приватным методом `gcd` по алгоритму Евклида; при отрицательном знаменателе знак переносится в числитель. Методы `sum`, `minus`, `mult`, `div` реализуют соответствующие формулы работы с дробями и каждый раз возвращают **новый** объект `Fraction`, не трогая поля `this` — это и обеспечивает неизменяемость. Деление дополнительно проверяет, что делитель не равен нулю. Для работы с обычным целым числом добавлена перегрузка каждого метода (`sum(int)`, `minus(int)`, `mult(int)`, `div(int)`) — она превращает число `n` в дробь `n/1` и вызывает уже готовый метод для двух дробей, не дублируя формулы. Поскольку каждый метод возвращает объект `Fraction`, у результата можно сразу вызвать следующий метод — так работает цепочка `f1.sum(f2).div(f3).minus(5)`.
