# Задание 1. Обобщённые классы и интерфейсы

## Задача 1
### Текст задачи
Коробка. Создать обобщённый класс `Box<T>`, который хранит один предмет любого типа. Методы: `put(T item)` — положить предмет, `T get()` — достать предмет (после этого коробка пустеет), `boolean isFull()` — проверка, заполнена ли коробка. Если коробка уже заполнена, а в неё пытаются положить предмет, выбрасывается исключение. Если коробка пуста, `get` возвращает `null`.

### Алгоритм решения
Класс параметризован типом `T`, предмет хранится в приватном поле `item`. Пустая коробка — это `item == null`, поэтому `isFull()` просто сравнивает поле с `null`.

В `put` две проверки: `null` положить нельзя (`IllegalArgumentException`), а если коробка уже заполнена — выбрасывается `IllegalStateException`. Метод `get` сохраняет предмет в локальную переменную, обнуляет поле и возвращает сохранённое значение, поэтому у пустой коробки он возвращает `null`. Конструктор с аргументом вызывает `put`, так что проверки работают и при создании. В `main` показаны создание коробки, заполнение, попытка положить второй предмет (ловится исключение) и извлечение.

## Задача 3
### Текст задачи
Сравнение. Создать обобщённый интерфейс `Comparing<T>` с методом `int compare(T other)`, который возвращает 1, если текущий объект больше `other`, -1, если меньше, и 0, если они равны. Реализовать его в классе `Book` (название и количество страниц): книги сравниваются по количеству страниц.

### Алгоритм решения
Интерфейс `Comparing<T>` описывает единственный метод сравнения с объектом того же типа. Класс `Book` реализует `Comparing<Book>`, поэтому параметр `compare` имеет тип `Book`, а не `Object`, и приведение типов не нужно.

Внутри `compare` количество страниц текущей книги сравнивается со страницами `other`: больше — возвращается 1, меньше — -1, иначе 0. В `main` сравниваются «Война и мир» (1225 страниц) и «Мцыри» (80 страниц) в обе стороны, а также книга с самой собой.

# Задание 2. Ограниченные типы и wildcard

## Задача 2
### Текст задачи
Максимум в коробках. Написать метод `double findMax(List<Box<? extends Number>> boxes)`, который принимает список коробок с числами разных типов (`Integer`, `Double`, `Long` и т. д.) и возвращает максимальное значение среди них. Значения из коробок не должны пропасть: после работы метода коробки остаются заполненными. Пустые коробки пропускаются.

### Алгоритм решения
Параметр `? extends Number` позволяет передать в одном списке коробки с разными числовыми типами, а общий метод `doubleValue()` даёт возможность сравнивать их как `double`.

Из-за wildcard вернуть извлечённое значение обратно в `Box<? extends Number>` напрямую нельзя — компилятор не знает точный тип. Поэтому используется вспомогательный обобщённый метод `readAndRestore(Box<T> box)` с ограничением `T extends Number`: компилятор «захватывает» wildcard в конкретный тип `T`. Метод проверяет `isFull()`, достаёт значение через `get()`, сразу кладёт его обратно через `put()` и возвращает `doubleValue()`; у пустой коробки возвращается `null`.

В `findMax` перебираются все коробки, максимум обновляется, если значение не `null` и больше текущего. Если все коробки пусты, выбрасывается `IllegalArgumentException`. В `main` проверка выполняется на коробках с `Integer`, `Double`, `Long` и одной пустой, а после поиска список выводится снова, чтобы показать, что значения на месте.

# Задание 3. Обобщённые методы и функциональные интерфейсы

В задании 3 используется класс `ListUtils` с обобщёнными статическими методами. Вместо лямбда-выражений поведение передаётся через собственные интерфейсы (`Transformer`, `Condition`, `Combiner`, `ResultFactory`, `ResultWriter`), которые реализованы отдельными вложенными классами в `Task3`.

## Задача 1
### Текст задачи
Преобразование. Написать метод `<T, P> List<P> transform(List<T> source, Transformer<T, P> transformer)`, который преобразует каждый элемент списка и возвращает новый список. Примеры: список строк → список их длин; список чисел → список модулей; список массивов → список максимальных элементов массивов.

### Алгоритм решения
Интерфейс `Transformer<T, P>` с методом `P apply(T value)` описывает преобразование из типа `T` в тип `P`. Метод `transform` создаёт пустой список результатов, проходит по исходному списку, применяет `apply` к каждому элементу и добавляет результат в новый список. Исходный список не меняется.

Реализации: `StringLength` (строка → длина), `AbsoluteValue` (число → модуль через `Math.abs`), `ArrayMax` (массив `int[]` → максимум, для пустого массива выбрасывается исключение).

## Задача 2
### Текст задачи
Фильтрация. Написать метод `<T> List<T> filter(List<T> source, Condition<T> condition)`, который оставляет в списке только элементы, удовлетворяющие условию. Примеры: убрать строки короче 3 символов; убрать положительные числа; оставить только те массивы, в которых нет положительных элементов.

### Алгоритм решения
Интерфейс `Condition<T>` с методом `boolean test(T value)` задаёт условие. Метод `filter` проходит по списку и копирует в новый список только те элементы, для которых `test` вернул `true`.

Реализации: `LengthAtLeastThree` (длина строки не меньше 3), `NotPositive` (число не больше 0 — то есть положительные убираются), `NoPositiveInArray` (перебирает массив и при первом положительном элементе возвращает `false`, иначе `true`).

## Задача 3
### Текст задачи
Свёртка. Написать метод `<T> T reduce(List<T> source, T initial, Combiner<T> combiner)`, который сводит список к одному значению. Примеры: список строк → одна строка (склейка); список чисел → их сумма; список списков → общее количество элементов во всех списках.

### Алгоритм решения
Интерфейс `Combiner<T>` с методом `T combine(T left, T right)` объединяет два значения в одно. Метод `reduce` начинает с начального значения `initial` и по очереди объединяет накопленный результат с каждым элементом списка.

Начальное значение передаётся явно (пустая строка для склейки, 0 для суммы), поэтому для пустого списка метод возвращает именно его — без `null` и без ошибок. Значение `null` в качестве `initial` запрещено (`IllegalArgumentException`). Реализации: `StringConcat` и `IntegerSum`.

Для списка списков задача решается в два шага: сначала `transform` с `ListSize` превращает каждый вложенный список в его размер, затем `reduce` с `IntegerSum` суммирует размеры.

## Задача 4
### Текст задачи
Сбор. Написать метод, который собирает элементы списка в новую коллекцию. Примеры: разделить список чисел на положительные и отрицательные (список из двух списков); сгруппировать строки по длине (отображение «длина → список строк»); получить множество уникальных строк.

### Алгоритм решения
Метод `<T, R> R collect(List<T> source, ResultFactory<R> factory, ResultWriter<R, T> writer)` не знает, какая именно коллекция получается, поэтому работа делится на два интерфейса: `ResultFactory<R>` создаёт пустой результат, а `ResultWriter<R, T>` описывает, как добавить в него очередной элемент. Метод создаёт результат через фабрику и в цикле передаёт в него каждый элемент списка.

Реализации:
- `PosNegFactory` / `PosNegWriter` — результат `List<List<Integer>>` из двух списков: положительные числа попадают в первый, отрицательные во второй, нули отбрасываются.
- `LengthGroupsFactory` / `LengthGroupsWriter` — результат `Map<Integer, List<String>>` на основе `TreeMap` (ключи отсортированы). Если для длины строки ещё нет списка, он создаётся, после чего строка добавляется в него.
- `UniqueFactory` / `UniqueWriter` — результат `Set<String>` на основе `LinkedHashSet`, который убирает повторы и сохраняет порядок первого появления.
